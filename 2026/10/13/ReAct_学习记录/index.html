本文讨论的是姚舜禹（Shunyu Yao）等人的 ReAct，即 Reasoning + Acting。论文题为 ReAct: Synergizing Reasoning and Acting in Language Models，发表于 ICLR 2023。

论文原文：arXiv 论文页面 · PDF 全文

阅读范围为论文第 1–4 节、附录 C.4 与 E.1。以下以学习理解为主，涉及实验的结论均限定在论文的具体设置下。

一、只推理与只行动，分别缺少什么？

先区分论文中的两个基线：CoT（Chain-of-Thought） 生成推理过程，但在这里不通过外部工具核实信息；Act可以与环境交互、获得观察，但轨迹中没有显式的 Thought。

纯 CoT 缺少外部核实机会，可能出现事实幻觉。如果后续推理继续依赖错误事实，错误就会沿着推理过程传播。

Act 即使拿到了外部信息，也可能无法正确整合证据或跟踪当前状态。论文图 1 中，Act 输出 Finish[yes] 的失败体现了答案综合的问题；ALFWorld 中反复尝试无效拿取，则体现了状态跟踪的问题。

这两类失败让我注意到两个不同环节：信息是否可靠，以及模型能否利用已有信息做出合适的下一步决策。

二、Thought、Action 与 Observation 如何形成协同？

ReAct 将思考与环境交互放进同一条任务轨迹。理解这条轨迹时，需要区分三种内容：

内容 由谁产生 在任务中的作用
Thought 模型 整理信息、形成判断、跟踪进度或制定计划
Action 模型生成，工具或环境执行 检索信息或与环境交互
Observation 工具或环境 返回行动结果，提供外部反馈

这里有两个方向的联系：

  • Reason to act： 推理指导下一步行动，比如决定还缺少什么证据、接下来应该检索什么。
  • Act to reason： 行动获取外部信息，让后续推理有新的依据。

我对“协同”的理解是：推理会改变行动选择，行动反馈也会改变后续推理。判断是否形成协同，需要看这两种影响是否发生。

为什么把 Thought 写出来可能有帮助？

Thought 可以把分散的信息整理成明确的判断、进度或计划。这些文字会进入后续上下文，成为模型继续生成的依据。例如，记录某个子目标已经完成，可以帮助后续行动转向下一个子目标。

因此，显式思考具有实际的上下文作用。不过，Act 没有显式 Thought，也不等于完全不能推断；更明确的提示同样可能改善 Act 的行为，论文没有证明它无法做到。

三、从行动空间与上下文理解 ReAct

论文第 2 节将 ReAct 表述为对行动空间的扩展：

A^=A∪L\hat{\mathcal A}=\mathcal A\cup\mathcal L A^=A∪L

其中，A\mathcal AA 是原有的环境行动空间，L\mathcal LL 是语言空间。加入 L\mathcal LL 后，模型可以选择生成一段思考。

思考会更新上下文，但不直接改变外部环境。 思考追加的是模型生成的判断；环境行动及其观察也会进入上下文，其中观察提供外部反馈。阅读轨迹时，需要分清哪些内容来自环境，哪些内容是模型对环境的解释。

图 1d 中的 Thought 与图 1 的 2b 部分中的 Act: Think，都可以放在这个框架下理解。

开放的语言空间为什么需要语言先验？

可以生成的思考内容非常多。模型既要判断何时思考，也要判断思考什么，这使扩展后的行动选择更加困难。

论文主要利用预训练模型已有的语言与知识能力，通过少量人工编写的任务轨迹，提示冻结参数的 PaLM-540B 生成思考与行动。示例轨迹为模型提供了如何组织任务过程的参考。

四、提示与微调：轨迹由谁产生？

笔记中容易混淆的一点，是“给模型看轨迹”和“用轨迹训练模型”的区别。

方式 是否更新模型参数 轨迹的用途
少样本提示 否 将人工编写的示例轨迹放入上下文，引导模型完成新任务
微调 是 用模型生成后筛选出的正确答案轨迹训练模型

在实际执行任务时，模型生成 Thought 和 Action，工具或环境执行行动，再返回 Observation。这里的观察是环境反馈，不能把它当成模型自行生成的事实依据。

理解 ReAct 时，需要同时看清示例来自哪里、是否更新参数，以及执行过程中每类内容的来源。

五、自由形式与稀疏思考，分别意味着什么？

自由形式描述的是思考内容：Thought 不限于固定模板，可以用于分解目标、更新进度、处理异常或调整计划。

稀疏思考描述的是思考出现的频率：多个行动可以沿用同一个计划，等到需要判断、更新进度或处理异常时，再生成新的 Thought。

两者是不同维度。自由形式的思考可以密集出现，也可以稀疏出现。论文的问答任务采用密集的思考与行动交替；交互决策任务允许模型在较长的行动序列中选择何时思考。

ReAct 与 ReAct-IM 的比较能说明什么？

ReAct-IM 使用接近 Inner Monologue 的密集、受限思考模式。在论文的 ALFWorld 设置下，ReAct 的灵活思考总体表现更好，但并非每项任务都优于 ReAct-IM。相关比较见论文第 4 节与表 3。

理解这组消融时，我保留了一个限制：实验同时改变了思考内容和密度，不能把表现差异全部归因于其中一个因素，也不能推出“思考越多、越全面越好”。

同样，轨迹出现循环可能与没有有效利用反馈有关，但论文没有证明稀疏思考本身会导致循环。分析失败时，仍然需要回到具体轨迹，检查模型如何解释观察、如何选择下一步行动。

六、编辑 Thought 为什么能改变行为？

Thought 会进入后续上下文，因此编辑它就可能改变模型接下来生成的行动。论文图 5 展示了通过编辑思考干预行动轨迹的案例，见论文全文。

这为显式思考的可检查性与可干预性提供了例子：人可以阅读模型当前表达的判断，并尝试修改它，使任务沿着调整后的计划继续进行。

但这个结论有边界。案例没有证明显式 Thought 完整反映了模型内部计算，也不保证任意编辑都会有效。阅读这些文字时，可以把它们看作影响后续行为的上下文，同时避免直接将其等同于模型全部的内部推理过程。

七、这次阅读留下的理解

读完这几节后，我会从三个问题检查一条 ReAct 轨迹：模型当前依据哪些信息做判断？这次行动是否带回了有用的反馈？下一步决策是否真正利用了这些反馈？

Thought 提供整理判断与计划的空间，Action 带来与外部环境交互的机会，Observation 则为后续判断提供反馈。对我来说，理解这几个环节如何相互影响，是这次阅读最主要的收获。后续阅读实验或实现时，我也会继续区分方法本身、具体提示设置与实验能够支持的结论。
